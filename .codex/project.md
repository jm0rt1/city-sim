# CitySim product context

The active product is the native SwiftUI/SpriteKit package at
`Native/CitySimNative`. Start with
[`docs/PRODUCT_RESTART_BRIEF.md`](../docs/PRODUCT_RESTART_BRIEF.md) and pursue
one bounded player-visible outcome at a time. Explicit user direction wins over
the stated sequence.

Use `swift build --package-path Native/CitySimNative`,
`swift test --package-path Native/CitySimNative`, and
`./script/build_and_run.sh` as appropriate. A build or test establishes only
its own claim. User-visible and UX work requires proof from the real native app
at exact 1280x800 and true 900x600.

One Goal Driver owns integrated planning and acceptance with a lightweight
liaison. Use at most one independent, short-lived specialist for a genuinely
bounded contribution. Select SOL/high for Goal Driver planning, cross-cutting
diagnosis, and acceptance; Terra/high for bounded isolated implementation; and
Luna/medium only for mechanical tests, benchmarks, or log collection. Do not
create agents merely to demonstrate delegation or restore workstreams,
hierarchies, claims, routes, ledgers, handshakes, dashboards, routine handoffs,
or ongoing agent assignments. Preserve unrelated legacy Python unless the user
explicitly targets it.
